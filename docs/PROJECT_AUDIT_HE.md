# דוח ביקורת פרויקט ואנליזת חורים (Project Audit & Gap Analysis)
**מערכת מנהל עבודה**

דוח זה מציג סקירה מעמיקה של קוד המערכת, הארכיטקטורה (Cloudflare D1/R2, IndexedDB ו-React) והלוגיקה העסקית, במטרה לאתר "חורים" ולשפר ביצועים, אמינות ואבטחה.

---

## 📋 סיכום מנהלים (Executive Summary)
המערכת בנויה בצורה מקצועית ומאובטחת ברובה (כולל בדיקת קובצי חתימה ב-R2 ומניעת כפילויות סנכרון). עם זאת, נמצאו מספר **"חורים" משמעותיים** בארכיטקטורה ובלוגיקה העסקית שעלולים לגרום להאטה משמעותית בייצור (Production), טעויות אנוש והצטברות קבצים יתומים.

---

## 1. ⚡ חורי ביצועים וארכיטקטורה (Performance & Architecture Gaps)

### 🚨 חור 1.1: אתחול Schema בכל בקשת API בשרת (ensureCoreSchema Bottleneck)
* **מיקום בקוד:** `app/api/state/route.ts`, שורות 349 ו-367.
* **הבעיה:** בכל בקשת `GET` או `POST` השרת מריץ את `ensureCoreSchema(db)` המבצעת סדרת שאילתות `CREATE TABLE IF NOT EXISTS` בתוך `db.batch`.
* **ההשלכה:** תוספת של 10-50ms לכל בקשה ועלייה דרסטית בצריכת השאילתות (Query Count) ב-Cloudflare D1, מה שמייקר את העלויות ומאט את חוויית המשתמש.
* **פתרון מוצע:** שימוש ב-Cache Flag גלובלי ברמת ה-Worker:
  ```typescript
  let schemaEnsured = false;
  async function ensureCoreSchema(db: D1Database) {
    if (schemaEnsured) return;
    // ... שאילתות האתחול ...
    schemaEnsured = true;
  }
  ```

### 🚨 חור 1.2: אינדקסים חסרים במסד הנתונים D1 (Missing DB Indexes)
* **מיקום בקוד:** `app/api/state/route.ts` בתוך `ensureCoreSchema`.
* **הבעיה:** חסרים אינדקסים על עמודות המפתח המשמשות לסינון וחיבור בכל בקשה:
  * בטבלאות `projects` ו-`clients` חסר אינדקס על `business_id`.
  * בטבלת `users` חסר אינדקס על `auth_user_id` (נצרך לזיהוי המשתמש בכל בקשה).
  * בטבלאות `attachments` ו-`audit_log` חסר אינדקס על `business_id`.
* **ההשלכה:** עם גדילת המידע, SQLite יבצע סריקות טבלה מלאות (Full-Table Scans), מה שיביא לקפיאה והאטה קשה בביצועים.
* **פתרון מוצע:** הוספת אינדקסים ייעודיים:
  ```sql
  CREATE INDEX IF NOT EXISTS idx_projects_business ON projects (business_id);
  CREATE INDEX IF NOT EXISTS idx_clients_business ON clients (business_id);
  CREATE INDEX IF NOT EXISTS idx_users_auth_id ON users (auth_user_id);
  CREATE INDEX IF NOT EXISTS idx_attachments_business ON attachments (business_id);
  ```

### 🚨 חור 1.3: פתיחה וסגירה תכופה של IndexedDB באופליין
* **מיקום בקוד:** `app/offline-store.ts` בפונקציה `transact`.
* **הבעיה:** בכל קריאה מקומית מבוצעים פתיחה וסגירה מלאים של בסיס הנתונים המקומי בדפדפן.
* **ההשלכה:** תקורה גבוהה בדפדפנים וסכנה לנעילת טרנזקציות בסנכרון מהיר.
* **פתרון מוצע:** שימוש בחיבור Singleton פתוח קבוע במהלך מחזור חיי האפליקציה.

## 2. 📅 חורי לוגיקה עסקית והזנת נתונים (Business Logic & Input Gaps)

### 🚨 חור 2.1: הזנת תאריכים עתידיים בטפסים
* **מיקום בקוד:** `app/page.tsx` בתוך `ManualTimeForm`, `PaymentForm` ו-`ExpenseForm`.
* **הבעיה:** שדות ה-`input` של התאריך מאפשרים בחירת תאריכים עתידיים ללא שום מגבלה.
* **ההשלכה:** טעויות אנוש עלולות להכניס דיווחים עתידיים (למשל שנת 2030) שיעוותו לחלוטין את הדוחות.
* **פתרון מוצע:** הוספת הגבלת `max` לתאריך הנוכחי:
  ```tsx
  const today = new Date().toISOString().slice(0, 10);
  // בטפסים: max={today}
  ```

### 🚨 חור 2.2: היעדר מגבלת סכום עליונה בטפסים כספיים
* **מיקום בקוד:** `app/page.tsx` בשדות `amount` של תשלומים והוצאות.
* **הבעיה:** ניתן להקליד כל סכום שהוא ללא גבול עליון קשיח.
* **ההשלכה:** השתרבבות ספרה בטעות עלולה להזין הוצאה של מיליוני אירו, מה שיכול לשבש את כל החישובים והגרפים וליצור שגיאות הצפת מספרים (Overflow).
* **פתרון מוצע:** הגבלת סכום הגיונית (למשל, `max="999999"`).

### 🚨 חור 2.3: טיימרים פעילים שנשכחו ללא הגבלה
* **מיקום בקוד:** `app/page.tsx` בשורה 1023.
* **הבעיה:** המערכת מתריעה לאחר 10 שעות פעילות של טיימר, אך מאפשרת לו לרוץ לנצח.
* **ההשלכה:** עובד ששכח לעצור טיימר עלול לגלות דיווח של מאות שעות שגויות שידרשו תיקון ידני מייגע.
* **פתרון מוצע:** עצירה אוטומטית קשיחה של טיימרים רצים לאחר 14 או 16 שעות.

## 3. 📂 חורי ניהול משאבים (Resource Gaps)

### 🚨 חור 3.1: קבצים יתומים באחסון ה-R2
* **מיקום בקוד:** `app/api/state/route.ts` בתוך `deleteProject`.
* **הבעיה:** מחיקת פרויקטים (שמעבירה אותם לסל המחזור) אינה מוחקת או מסמנת את הקבלות והמסמכים שלהם שנשמרו ב-R2 ובטבלת `attachments`.
* **ההשלכה:** הצטברות קבצים יתומים ללא קישור באחסון ה-R2, מה שמנפח את שטח האחסון ומייקר עלויות בטווח הארוך.
* **פתרון מוצע:** ניקוי אוטומטי של כל הקבצים המשויכים בעת מחיקה מלאה של פרויקט/הוצאה.
