# חשבונות ואימות

המערכת משתמשת בחשבונות פנימיים המבודדים באמצעות `business_id`. הרשמה יוצרת עסק חדש וריק ומשתמש מנהל יחיד באותה פעולת D1.

- סיסמאות נשמרות כ־PBKDF2-SHA-256 עם salt אקראי ו־310,000 סבבים; הסיסמה עצמה אינה נשמרת.
- session נשמר ב־cookie בשם `menahel_session` עם `HttpOnly`, `SameSite=Lax`, וב־HTTPS גם `Secure`. תוקפו מתחדש לשנה בכל שימוש מוצלח, ולכן משתמש פעיל נשאר מחובר עד התנתקות; session לא פעיל פג לאחר שנה.
- במסד נשמר רק SHA-256 של token ה־session.
- כניסה מוגבלת ל־10 ניסיונות כושלים לכל שילוב IP ומייל במשך 15 דקות.
- תמונות פרופיל מוגבלות ל־JPG/PNG/WEBP עד 5MB, נבדקות גם לפי חתימת הקובץ ונשמרות ב־R2 פרטי.
- `auth_tokens` מוכן לטוקני אימות מייל ואיפוס סיסמה. הפעלת המשלוח דורשת בחירת ספק מיילים והגדרת מפתח API ושולח מאומת.
- מסך הפרופיל מאפשר לעדכן שם, טלפון, כתובת מייל ותמונת פרופיל, וכן להחליף סיסמה לאחר אימות הסיסמה הנוכחית. החלפת סיסמה מנתקת את כל הסשנים האחרים.
- הטעינה הראשונית מציגה מסך ניטרלי בלבד עד לאימות החשבון; נתוני דמו אינם נשלחים או מוצגים בדומיין הציבורי.

לפני production יש להריץ את migrations `0010`–`0012`, לבדוק HTTPS ו־`Secure` cookie, ולבצע תרחיש עם שני חשבונות אמיתיים שמוודא שאין מעבר מידע ביניהם.
