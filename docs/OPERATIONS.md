# תפעול ותחזוקה — מנהל עבודה

## מצב הפריסה

- סביבת ההדגמה הציבורית: `https://menahel-avoda.er2829288.workers.dev/`.
- בדיקת בריאות: `GET /api/state?health=1` מחזירה `status: ok` רק כאשר ה־Worker ו־D1 זמינים.
- מצב האורח נשאר פעיל במכוון. אין להזין בסביבה הציבורית מידע אמיתי או רגיש.

## בדיקות לפני פריסה

1. `npm run check`
2. בדיקת מובייל ודסקטופ.
3. בדיקת טיימר, דיווח ידני, תשלום, הוצאה והעלאת קובץ.
4. בדיקת אופליין: טעינה אונליין, מעבר לאופליין, פעולה, רענון וחזרה לאונליין.
5. `npm run deploy`
6. בדיקת HTTP 200, בדיקת הבריאות וה־headers של האבטחה בדומיין הציבורי.

## גיבוי D1

- הפעלה: `npm run backup`.
- קובצי הגיבוי נוצרים תחת `backups/` ואינם נכנסים ל־Git משום שהם עשויים להכיל מידע עסקי.
- יש להעתיק גיבוי תקופתי לאחסון מוצפן ונפרד מהמחשב ומהחשבון שמארח את היישום.
- שחזור הוא פעולה הרסנית ולכן אינו אוטומטי. לפני שחזור יוצרים גיבוי חדש, בודקים את יעד ה־D1 ומייבאים את קובץ ה־SQL דרך Wrangler לפי נוהל Cloudflare העדכני.

## קבצים ב־R2

- מטא־הנתונים נשמרים ב־D1 והתוכן ב־R2.
- יש להפעיל מדיניות שמירה או שכפול עבור bucket `site-creator-r2` דרך Cloudflare לפני מעבר לנתונים אמיתיים.
- מחיקת קובץ באפליקציה היא פעולה מכוונת ומסירה את האובייקט מ־R2; שחזור מסל המחזור אינו חל על קבצים.

## ניטור ותגובה לתקלה

- בדיקת הבריאות מיועדת לניטור חיצוני בתדירות של 5 דקות.
- במקרה כשל: בודקים תחילה את גרסת ה־Worker, אחר כך D1 ו־R2, ולאחר מכן את תור הסנכרון באייקון שבכותרת.
- פעולות ליבה נשמרות מקומית וממשיכות להופיע בממשק בזמן תקלה. אין לנקות נתוני דפדפן לפני שהמונה חזר לאפס.
- חזרה לגרסה קודמת נעשית דרך Cloudflare Worker Versions; לאחר rollback בודקים בריאות ופעולת קריאה לפני כל שינוי נתונים.

## החלטות סופיות לגרסה הראשונה

- שעות מחושבות לפי הזמן המדויק שנרשם, ללא עיגול אוטומטי. כך נמנע שינוי כספי נסתר; אם צריך עיגול, מבצעים אותו בדוח חיצוני או מגדירים כלל מוצר חדש.
- אין מחיקה לצמיתות של לקוחות, פרויקטים או עובדים בגרסה הראשונה. השחזור נשאר זמין בסל המחזור.
- עובד יכול לערוך או למחוק דיווח של עצמו לאחר עצירת הטיימר. מנהל יכול לתקן דיווחים של העסק, וכל שינוי נרשם בהיסטוריה.
